# Lab 4: Document Extraction and Requirements Summary — แนวทางการประเมิน

**กลุ่มเป้าหมาย:** Developer  
**ระยะเวลา:** 10–20 นาที  
**เครื่องมือ:** อนุญาตให้ใช้ AI  
**ข้อมูลตั้งต้น:** ไฟล์ PowerPoint และค่าการเชื่อมต่อ LLM ใน `.env`

## 1. สิ่งที่ต้องการประเมิน

| สิ่งที่ประเมิน | พฤติกรรมที่คาดหวัง |
|---|---|
| การใช้ AI | ให้บริบทโจทย์และข้อจำกัดแก่ AI แล้วตรวจและปรับผลงานที่ได้ |
| การดึงข้อมูล | เขียน function อ่าน PowerPoint และสร้าง Markdown ที่แยกสไลด์และรักษาบริบทข้อมูล |
| การเชื่อมต่อ LLM | ส่ง Markdown ที่ดึงได้ให้ LLM จริง และจัดการข้อผิดพลาดที่เกิดขึ้น |
| การวิเคราะห์ requirement | แยกความต้องการจากข้อมูลประกอบ โดยไม่แต่งข้อมูลเพิ่มหรือสรุปเกินหลักฐาน |
| การตรวจสอบ | อ้างอิงสไลด์และตรวจความถูกต้องของสรุปเทียบกับต้นฉบับ รวมถึงระบุข้อมูลที่ดึงไม่ได้ |
| การส่งมอบ | มีวิธีติดตั้งและรัน พร้อมไฟล์ผลลัพธ์ทั้งสองประเภท |

## 2. แนวทางตรวจผลงาน

- เอกสารต้นทางมี 14 สไลด์ ประกอบด้วยข้อความ ตาราง และภาพประกอบ ให้ตรวจว่าผลลัพธ์ระบุสไลด์ครบ รวมถึงสไลด์ที่ไม่มีข้อความซึ่งดึงได้
- เลือกตรวจข้อความภาษาไทยและตารางอย่างน้อยหนึ่งตัวอย่าง ว่ายังคงความหมายและความสัมพันธ์ของข้อมูล การดึงจากภาพอาจต้องใช้ OCR หรือวิธีอื่น ให้ผู้สอบระบุส่วนที่ทำไม่ได้ ไม่ควรถือว่าข้อความจากภาพถูกดึงครบโดยอัตโนมัติ
- เลือก requirement อย่างน้อยสองข้อจากสรุป แล้วตรวจหมายเลขสไลด์และข้อความต้นฉบับว่ารองรับข้อสรุป ตัวอย่างจุดตรวจคือเป้าหมายการนำเข้าครั้งละมากสุด 6,000 คนในสไลด์ 6 และขั้นตอนการเตรียมข้อมูลและนำเข้าของ HR ในสไลด์ 11
- ตรวจว่า Markdown ที่สร้างถูกส่งให้ LLM จริง ผลสรุปไม่ใช่ข้อความที่เขียนเตรียมไว้ และมีขั้นตอนตรวจการเรียกจริงแยกจากการทดสอบด้วย mock หากผู้สอบมี
- ทดลองกรณีไฟล์ไม่ถูกต้องและจำลองการเรียก LLM ไม่สำเร็จ ต้องแสดงข้อผิดพลาดที่เข้าใจได้โดยไม่เผย API key
- ความเชื่อมโยงกับเอกสารสำคัญกว่ารูปแบบสรุปที่ตายตัว ให้พิจารณาเนื้อหาที่ดึงไม่ได้และข้อจำกัดที่ผู้สอบระบุ

ผู้จัดสอบควรเตรียม runtime, dependency, `.env` และตรวจการเชื่อมต่อ LLM ก่อนจับเวลา หากบริการ LLM ไม่พร้อม ให้บันทึกข้อจำกัดและประเมินเฉพาะส่วนที่ตรวจได้ ไม่ถือว่าการทดสอบด้วย mock พิสูจน์การเชื่อมต่อจริง

## 3. เกณฑ์การให้คะแนน

| หัวข้อ | คะแนน | แนวทางพิจารณา |
|---|---:|---|
| การดึงข้อมูลเป็น Markdown | 30 | มี function อ่านเอกสาร บันทึก Markdown พร้อมเลขสไลด์ และรักษาบริบทข้อความหรือตาราง |
| การเชื่อมต่อ LLM | 20 | ส่ง Markdown ให้ LLM และบันทึกผลสรุปแยก พร้อมจัดการข้อผิดพลาด |
| คุณภาพสรุป requirement | 25 | สรุปตรงกับเอกสาร อ้างอิงสไลด์ และแยกข้อเท็จจริงจากสิ่งที่ไม่ชัดเจน |
| การตรวจสอบและข้อจำกัด | 15 | ตรวจเทียบต้นฉบับ ระบุเนื้อหาที่ดึงไม่ได้ และมีวิธีรันที่ทำตามได้ |
| การใช้ AI | 10 | แสดง prompt ที่สำคัญและอธิบายการตรวจหรือปรับผลลัพธ์จาก AI |
| **รวม** | **100** | |

ให้คะแนนตามหลักฐานและส่วนที่ทำงานได้จริง พิจารณาคะแนนบางส่วนเมื่อส่งงานไม่ครบ และตรวจว่าไม่มี credential ในผลงานหรือ log ที่ส่ง
